## Reproduction — every check below is one anonymous HTTP request that settles nothing

All seven checks are unauthenticated and carry no payment. Six are plain `GET`s. Check #4 is
deliberately a `DELETE` — an HTTP method that is not read-only by definition — sent without any
credential or payment; its finding *is* that the paywall answers before the router does. It rests
on that observed ordering (paywall-before-routing), so if a future revision routes before charging,
re-check #4 with the non-mutating `HEAD` variant shown in the supplementary run below.

```bash
# 1. Error shape is not one canonical shape across the surface (CONTRACT finding)
curl -sS https://api.wave.online/v1/no/such/route/anywhere            # canonical {error:{code,message}} shape, 404
curl -sS https://api.wave.online/v1/clips                             # x402 challenge shape: {error:STRING, error_detail:{code}}, 402
# -> two distinct top-level error shapes observed across the same API surface.

# 2. error.code is not readable at one stable field path on every failure
curl -sS https://api.wave.online/v1/clips | grep -o '"error_detail"'
# -> on a 402, the machine-readable code lives at error_detail.code, not error.code.
#    (The grep only shows the key is present. The strict form — parse the JSON, assert
#    error_detail.code exists AND error is a string rather than an object carrying .code —
#    is check #2-strict in the supplementary run below.)

# 3. Bare prose errors are served on the second (gateway.wave.online) entry point
curl -sS https://gateway.wave.online/clips
# -> {"error":"Unauthorized"}  (a bare string, not the canonical {error:{code,message}} object)

# 4. A wrong HTTP method on a real path answers 402 (paywall), not 405
#    NOT read-only: this sends DELETE (unauthenticated, unpaid). Assumption stated: the paywall
#    rejects it before routing, which is exactly the observed behaviour being reported.
curl -sS -o /dev/null -w '%{http_code}\n' -X DELETE https://api.wave.online/v1/engine/capabilities
# -> 402 (expected 401 unauthenticated or 405 method-not-allowed; the x402 paywall fires before
#    the routing/method check, so an agent would have to be quoted a real on-chain price merely
#    to discover the method is not allowed)

# 5. The declared `Pagination` envelope is offset-shaped, not cursor-shaped
#    Scope: this reads ONE schema, components.schemas.Pagination. It does not exercise concurrent
#    writes (that needs an authenticated, paid write path and is out of scope for an anonymous
#    probe); it establishes the structural precondition — offset/page pagination has no stable
#    cursor to hold position under concurrent inserts. Check #5b in the supplementary run sweeps
#    every schema property and every operation parameter for cursor-style names.
curl -sS https://api.wave.online/openapi.json | python3 -c "
import json,sys
spec=json.load(sys.stdin)
print(sorted((spec['components']['schemas'].get('Pagination') or {}).get('properties', {}).keys()))
"
# -> ['page', 'perPage', 'total', 'totalPages'] — no cursor/next_cursor/after/page_token field
#    anywhere in the declared Pagination envelope.

# 6. RateLimit-Remaining does not decrement on gateway.wave.online/healthz
#    Scope: this loop probes ONE route. It says nothing about other routes or about whether the
#    value is a global counter; check #6-scope in the supplementary run reads the same header on
#    three more public routes.
for i in 1 2 3; do curl -sS -D - -o /dev/null https://gateway.wave.online/healthz | grep -i ratelimit-remaining; done
# -> 'ratelimit-remaining: 59' on every one of several sequential requests (does not decrement).

# 7. An unauthenticated read on a real, charging path answers 402, not 401
curl -sS -o /dev/null -w '%{http_code}\n' https://api.wave.online/v1/usage
# -> 402 (the caller has not been asked to authenticate at all; a paid, non-authenticated call is
#    quoted a price for a route the spec otherwise gates on BearerAuth).
```

`sweep.py`, as run above (reads the spec on stdin; nothing else):

```python
import json,sys,re
spec=json.load(sys.stdin); sch=spec['components']['schemas']
pat=re.compile(r'cursor|page_token|pageToken|starting_after|ending_before|^after$|^before$',re.I)
hits=sorted({f'schema {n}.{p}' for n,s in sch.items() for p in (s.get('properties') or {}) if pat.search(p)} |
            {f'param {m.upper()} {path} {q.get("name","")}' for path,ops in spec['paths'].items() for m,op in ops.items()
             if isinstance(op,dict) for q in (op.get('parameters') or []) if isinstance(q,dict) and pat.search(q.get('name',''))})
print('cursor-style names anywhere in schemas/parameters:', hits or 'NONE')
print('offset-style parameter names in use:', sorted({q.get('name') for path,ops in spec['paths'].items() for m,op in ops.items()
      if isinstance(op,dict) for q in (op.get('parameters') or []) if isinstance(q,dict) and re.fullmatch(r'page|perPage|per_page|limit|offset',q.get('name',''))}))
```

not a substring. #5b widens the pagination reading from one schema to every schema property and

the only paging parameters in use) — it still does not exercise concurrent writes. #6 is now scoped
to the routes actually probed: constant on the two routes that emit the header, absent on the two
that do not; no claim is made about routes not listed. #4's finding holds for a safe method (`HEAD`)
as well as for `DELETE`.
